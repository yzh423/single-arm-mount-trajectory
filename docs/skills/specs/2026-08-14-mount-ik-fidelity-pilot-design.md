# Mount / IK 跨保真漏斗试验设计

日期：2026-08-14

## 1. 目标

验证一种新的单臂安装位姿搜索流程，解决当前 4096 候选初筛与真实 URDF 完整 episode 求解相关性低、只传递一个 GPU winner、严格完整复评候选过少，以及所谓 rolling multibranch 实际没有使用 horizon 的问题。

本阶段是机制 A/B 试验，不启动十臂正式实验。试验使用当前已经修正的官方模型、TCP、底座碰撞、桌面碰撞和自碰撞定义。

## 2. 试验范围

- 数据：`pick-right-left/teleop_20260805_154215`，保持前后各裁剪 0.15 s。
- 机械臂：xArm6 与 OpenArm。
- 安装自由度：X、Y、Z、Yaw；Tilt=0、Roll=0。
- 安装边界：X `[-0.50, 0.50] m`、Y `[-0.55, 0.25] m`、Z `[0.02, 0.65] m`、Yaw `[-180, 180] deg`。
- 最终成功定义：所有保留帧均满足位置、姿态、关节连续性、速度、关节限制、状态碰撞和扫掠碰撞约束，完整 episode 才记为成功。
- 不修改原始数据、官方 URDF 或既有正式报告；所有试验结果写入新的 pilot 输出目录。

## 3. 候选漏斗

### 3.1 广域候选

保留 4096 个确定性 scrambled-Sobol 候选。该级只执行不会依赖 IK 分支选择的硬约束：真实桌面安装边界、底座占地、安装参数范围和明显的距离下界/上界不可达。

胶囊 IK 与胶囊碰撞只产生排序特征，不得作为候选硬淘汰依据，也不得声明完整 episode 成功。

### 3.2 多样 shortlist

从广域候选中保留 256 个候选。选择方式是代理得分与安装空间 farthest-point diversity 的组合，确保多个不同 X/Y/Z/Yaw 区域被保留。输出必须保存每个候选的 ID、mount、代理指标、空间区域和晋级原因，不能只保存 winner。

### 3.3 真实 URDF 连续窗口复筛

从 256 个候选中选择 128 个进行真实 MuJoCo 复筛。每个候选使用相同的官方 URDF、TCP 和碰撞词汇。窗口必须连续且携带真实时间戳，包括：

- episode 开头和结尾；
- 平移速度、角速度或曲率较高的区域；
- 第一轮严格求解暴露的失败区域。

每个窗口独立初始化，因此窗口结果只用于候选风险排序，不能被标记为完整 episode 成功。

### 3.4 完整 episode 与局部精修

窗口复筛后保留 24 个候选进行完整 chronological episode 求解。至少保留 4 个不同 mount 区域。随后在这些区域周围生成严格局部候选，并完整复评 8 至 12 个 finalist。

只要任一最终状态或扫掠边发生真实碰撞，该候选即为硬不可行。没有碰撞但无法满足目标 pose 的安全 hold 仍可记录，但完整 episode 失败。

## 4. 统一 IK 设计

把“候选生成”和“路径选择”分离：

1. 每一帧从多个延续种子和确定性全局种子生成多个去重后的 6D IK 解。
2. 每个候选解记录位置误差、姿态误差、关节限位裕量、奇异性裕量和状态碰撞。
3. 相邻帧候选之间建立边，使用真实 `dt` 检查速度、单帧跳变和扫掠碰撞。
4. 在有限 horizon 上执行 beam / receding-horizon 路径选择；`horizon` 必须真实影响规划结果，不允许被忽略。
5. 候选层为空时保持最后安全状态，并明确记录原因：pose 不可达、状态碰撞阻塞、边碰撞阻塞、速度阻塞或数值迭代失败。

试验同时输出两套速度口径：

- common-limit：所有机械臂使用同一逐关节速度上限，用于比较构型、轴数和臂展；
- native-limit：使用官方逐关节速度限制，用于评估硬件现实性。

若模型来源没有可信速度数据，该机械臂只进入 common-limit 排名，并在报告中标注。

## 5. 排序目标

最终排名继续以完整 episode 成功为第一优先级。搜索期间使用下列词典序，避免二元指标过于稀疏：

1. 完整 episode 成功；
2. 成功帧数；
3. 最长连续失败区间；
4. 状态/扫掠碰撞帧数；
5. 速度或关节跳变失败数；
6. 最差与 P95 位置误差；
7. 最差与 P95 姿态误差；
8. 最小关节限位、奇异性和碰撞裕量。

代理阶段不允许用独立逐帧 IK 的“全帧有解”替代上述完整轨迹定义。

## 6. 可观测性与 A/B 指标

新旧流程使用同一 episode 和机械臂，分别记录：

- coarse 与 strict 排名的 Spearman 相关；
- strict top-K 对真实 top 候选的 recall@K；
- coarse 完整成功乐观误判率；
- 晋级候选的安装空间覆盖；
- 完整 episode 成功、帧覆盖率和最长失败区间；
- 各失败原因计数；
- 每一级候选数、求解帧数、GPU/CPU 耗时和缓存命中；
- 最终 mount 与旧 mount 的差异；
- 状态碰撞与扫掠碰撞完整性。

每一级结果采用原子写入并可断点续跑。缓存指纹至少包含 episode 内容、模型文件、TCP、碰撞配置、安装边界、IK 参数和候选 ID。

## 7. 验收标准

代码级验收：

- 单元测试证明 4096 候选不会只输出一个 winner；
- 单元测试证明 shortlist 同时考虑得分和空间多样性；
- 单元测试证明 horizon 改变候选路径可见范围；
- 单元测试证明状态碰撞和扫掠碰撞候选不会进入最终路径；
- 单元测试证明窗口不能被误标为完整 episode 成功；
- 单元测试证明候选级 coarse/strict 映射可计算 recall@K 与 Spearman；
- 原有相关回归测试全部通过。

试验级验收：

- xArm6 和 OpenArm 都生成完整候选漏斗、A/B 指标、严格缓存和失败原因；
- 新流程严格 full-episode finalist 不少于 24 个，除非硬物理裁剪后不足；
- 真实 top 候选必须能追溯到其 coarse 候选 ID；
- 产生一份 pilot Markdown/JSON 报告和每臂一个 MuJoCo 视频；失败也必须渲染；
- 不把 pilot 结果写入正式十臂排名。

## 8. 非目标

- 本阶段不重跑十臂或全部 Local 任务。
- 不调整任务姿态、不做机器人特异的目标方向校准。
- 不缩放机械臂长度。
- 不用动力学控制结果替代当前运动学轨迹可行性结论；动力学控制作为后续独立实验。

## 9. 实施顺序

1. 先增加候选级日志、多样 shortlist 和跨保真统计测试。
2. 再实现通用的真实逐帧多候选层与有限 horizon 路径选择。
3. 将新求解器接入 mount 窗口复筛和完整 episode 阶段，旧流程保留为 A/B baseline。
4. 运行小型 smoke 测试，再运行 xArm6/OpenArm pilot。
5. 验证缓存、报告、失败视频和碰撞完整性后给出是否扩大到十臂的建议。
