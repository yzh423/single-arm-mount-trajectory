# PiperX 双任务严格完全跟随实验设计

日期：2026-08-20
状态：已批准（用户要求直接采用推荐方案实施并持续优化）

## 1. 目标与成功标准

在同一条可复算证据链上完成 `8-11/Fold_Box:161044` 与
`8-11/Seal_Bag:161504` 的 PiperX 双臂跟随实验。每个原始目标位姿都必须以
位置误差不超过 1 mm、姿态误差不超过 0.5° 为严格 IK 成功条件；不允许通过
删除、抽稀或替换失败目标提高覆盖率。

“完全 follow”被拆成四个不可混淆的结论：

1. 原始目标位姿严格 IK 覆盖率；
2. 原始时间戳下的动力学接受率；
3. 在保持目标顺序和目标位姿不变时，经速度/加速度受限重定时后的可执行率；
4. 精确执行结点及结点间插值边的碰撞状态。

主目标是两任务原始目标位姿覆盖率与重定时执行率均达到 100%。碰撞安全是独立
优化目标：在不牺牲严格覆盖率的前提下最大化无碰撞帧比例，并明确残余碰撞，
不得把碰撞帧标成安全或把视觉渲染当作真机许可。

## 2. 数据与固定约束

- Fold_Box 使用 `data/factory/8-11/Fold_Box/handheld_20260811_161044.csv`。
- Seal_Bag 使用 `data/factory/8-11/Seal_Bag/handheld_20260811_161504.csv`。
- 两任务均注册到工厂世界坐标并重采样到 60 Hz；首尾时刻必须保留。
- 机器人模型、关节限位、速度/加速度限位和官方 mesh 保持当前 PiperX 合同。
- 工具坐标旋转优先使用任务配置中的固定 `R_tool`，否则使用已审计标定工件。
- 接受阈值固定为 1 mm / 0.5°，优化器不得放宽。
- 视频使用 MuJoCo 离屏真实仿真场景渲染执行时间轴，不制作示意动画冒充结果。

## 3. 推荐方案

### 3.1 统一任务执行器

将现有 Fold_Box 专用完整跟随入口泛化为双任务入口。场景构建按构型传入
`mount_support_mode`：直立构型沿用 base yaw；水平或倒置构型由
`mount_quaternions` 计算真实 base quaternion，再交给场景构建器。输出文件名包含
任务与 take，避免双任务互相覆盖。

执行器继续采用多分支 IK、warm start、全局 rescue、翻腕候选与受限重定时。
生成的 NPZ 必须同时保存源时间轴、执行时间轴、源到执行映射、目标与实际 TCP、
逐侧误差、候选数量、rescue 标志、精确状态碰撞和入边碰撞。

### 3.2 Seal_Bag 的检测—优化闭环

候选按以下阶梯评估，全部先执行 `--no-video`：

1. PDF 推荐的 `horizontal_forward` 构型；
2. 历史报告中严格覆盖较高的直立构型；
3. 已有三构型筛选结果中的最佳候选；
4. 以当前最优为中心，对左右 base XY、共享 Z 与 yaw 做确定性局部搜索。

候选按字典序选择：严格双臂覆盖率、重定时执行率、碰撞无关的最大误差裕量、
无碰撞帧比例、原时序接受率、执行总时长。任何覆盖率低于当前最优的候选都不能
仅凭碰撞更少胜出。局部搜索在连续若干轮无严格改进或达到 100% 覆盖且碰撞指标
不再改进时停止，并保存每轮候选和淘汰原因。

### 3.3 Fold_Box 回归

Fold_Box 先复跑无视频基线，必须复现已发布的 1061/1061 严格覆盖和 1061/1061
重定时执行。若回归失败，停止正式渲染并修复根因；若通过，沿用经过哈希审计的
现有正式视频，避免同一轨迹重复渲染产生无意义差异。若共享代码改变执行轨迹，
则重新渲染并替换其工件。

### 3.4 报告和视频

最终生成一个双任务 PDF、两个 MP4（每任务一个）、一个机器可读双任务总表和
每任务 summary/NPZ/scene/provenance。PDF 的每个数字都从最终 JSON/NPZ 重新计算，
至少包含：构型、帧数、严格覆盖、固定时序、重定时时长、误差极值、速度/加速度
极值、碰撞结点/入边、优化迭代、失败候选、适用边界和真机前置检查。

## 4. 备选方案与取舍

- 仅沿用旧 fixed-time 流程：实现快，但它把动力学失败和 IK 不可达混在一起，且
  旧 Seal_Bag 结果不满足 1 mm / 0.5°，不采用。
- 对目标轨迹做平滑或修改：可能提高表面覆盖率，但不再证明原始目标完全 follow，
  不作为主结论；若作为诊断实验，必须单列且不能替代原始目标结果。
- 只优化碰撞：会牺牲严格覆盖主目标，不采用。碰撞只在等覆盖候选间参与选择。
- 从零做全局随机搜索：计算成本和复现成本高。采用报告候选加确定性局部细化，
  每个候选可重放、可审计。

## 5. 验证与发布门槛

实现前先增加失败测试，覆盖非直立场景方向、任务级命名、候选排序和跨任务证据
校验。完成后运行相关测试、完整测试、两任务无视频复跑、视频解码与帧数检查、
PDF 文本及逐页渲染检查、README 链接检查。

只有以下条件全部满足才提交并推送：

- 两任务的原始严格覆盖和重定时执行达到最终报告声明值；
- 报告、summary、NPZ、scene、provenance 与视频 SHA-256 一致；
- 所有视频可完整解码，PDF 无裁切、重叠、乱码或空白页；
- README 明确区分“完全位姿跟随”和“碰撞安全”；
- Git 只纳入权威源数据、代码、测试、文档与精选工件，不提交批量搜索缓存。
