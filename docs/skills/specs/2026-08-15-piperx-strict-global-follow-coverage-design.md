# PiperX 有界姿态适配下的双臂轨迹覆盖率优化设计

日期：2026-08-15

## 1. 背景与目标

当前 PiperX fixed-time 结果已经满足最终状态碰撞和扫掠碰撞为零，但 Seal Bag 与 Fold Box 仍存在大量 `dynamic_limit`、`state_collision`、`paired_branch_discontinuity` 和严格 6D IK 不可达帧。已有审计显示，当前固定 mount 与固定标定下的静态安全 6D IK 覆盖率明显高于最终跟随覆盖率，因此仍有一部分损失来自候选生成和跨帧联合选解，而不是目标本身不可达。

本设计的目标是在保留位置、时间、动力学和碰撞硬限制的前提下，通过有界且连续的姿态适配提高两个任务的同步跟随覆盖率，并准确区分无法改进的物理不可达帧。首要顺序为：

1. 保证所有硬约束不回退。
2. 修复容差范围内仍被误判为动态不连续的问题。
3. 减少局部 beam 剪枝造成的双臂分支断裂。
4. 在代表性失败区间验证收益后再运行完整轨迹。

## 2. 不可改变的约束

- 使用原始逐帧双臂位置目标，不插值、平滑或投影位置。
- 使用原始时间戳，不重定时、不跳帧改变时间基准。
- 对适配后的目标，位置误差不超过 1 mm，姿态跟踪误差不超过 1.5°。
- 关节速度不超过 3.14 rad/s，单帧关节跳变不超过 35°。
- PiperX 手爪相对法兰的变换严格采用机器人模型中的固定变换。
- 左右手持数据坐标系到 PiperX TCP 的固定标定在两个任务间共用；允许在物理合理的离散轴映射附近做每轴不超过 ±15° 的固定微调。
- 允许对工具轴和完整姿态做有界的逐帧适配，但必须保留原始四元数的相对变化、限制偏离幅度和帧间变化，并优先使用工具轴自由度。
- mount 保持竖直安装和相同 Z，只使用已允许的 XY、yaw、Z 搜索范围。
- 双臂状态碰撞与相邻帧扫掠碰撞均为硬约束。
- 指定跨臂几何对的最小仿真间隙保持不低于 15 mm。
- 不以加速度、实机控制平滑度或视觉美观替代上述 fixed-time 成功判据。

## 3. 根因判断

现有候选生成器主要把末端残差收敛到接近零，再按误差和关节代价排序。这会遗漏两类重要解：一类是末端位姿没有达到数值上的最小残差，但仍严格位于 1 mm / 1.5° 跟踪容差盒内，并且比零残差解更接近上一帧关节状态；另一类是原始姿态稍作物理允许的调整后即可形成连续安全分支的解。固定时间步约为 12.4 ms 时，速度限制只允许约 2.23° 的关节运动，因此这两类解都可能决定边是否可连接。

此外，当前滚动 beam 是前向局部搜索。某个分支当前代价较小，不代表它在几十或几百帧后仍有安全连接；未来可行但当前略贵的分支可能被提前剪掉，最终形成 `paired_branch_discontinuity`。仅扩大随机种子或 beam width 会显著增加运行时间，却不能系统解决这两个问题。

## 4. 总体方案

采用三阶段、可回退的增量实现。

### 4.1 有界姿态适配

姿态适配按从低自由度到高自由度的顺序启用，避免直接把完整姿态变成任意优化变量：

1. 先联合优化左右固定标定旋转。候选来自物理合理的离散轴排列和符号组合，并在最佳候选附近做每轴不超过 ±15° 的固定微调。Seal Bag 与 Fold Box 共用同一组左右固定四元数。
2. 对固定标定下仍无安全连接的帧，先允许绕工具轴做小幅调整。默认软目标为不超过 ±15°，绝对上限为 ±30°。
3. 工具轴调整仍不足时，才允许完整姿态小幅调整。摆动方向默认软目标为不超过 7.5°，绝对上限为 15°；工具轴仍使用前述上限。

逐帧适配不是独立求解。优化目标同时惩罚相对原始姿态的偏离、姿态偏移的一阶变化和二阶变化，并对左右手在共同操作阶段的相对姿态变化增加一致性代价。原始姿态始终是零代价中心；只有原始姿态不存在安全可连接分支时，才逐级开放工具轴和完整姿态适配。

每帧保存原始目标四元数、适配四元数、工具轴偏移角、摆动偏移角及触发原因。渲染和统计必须明确区分“原姿态严格跟随”和“有界姿态适配跟随”。

### 4.2 容差盒连续 IK

在现有 `MuJoCoCandidateGenerator` 上增加可选的 reference-aware 候选生成接口。它不追求零末端残差，而是在严格位姿容差内最小化相对参考关节状态的运动：

```text
minimize  ||wrap(q - q_ref)||² + joint_limit_penalty + singularity_penalty
subject to
  joint_lower <= q <= joint_upper
  position_error(q) <= 1 mm
  orientation_error(q) <= 1.5 deg
```

参考状态来自当前联合规划前沿中的左右臂状态，并可包含反向生成得到的后继参考。优化器必须使用显式关节边界；输出仍需经过现有严格 FK 误差、关节限位、奇异性、自碰撞和单臂环境碰撞复核。任何约束不通过的结果不得进入候选层。

新接口与原有多种子 DLS/SLSQP 路径并存。原有候选负责覆盖不同肩、肘、腕分支；reference-aware 候选只补充更容易从相邻帧连接的严格解。候选去重使用周期关节差，并在保留姿态分支多样性的同时限制每帧候选总量。

### 4.3 双臂离线候选图

对目标区间预计算左右臂严格候选层，来源包括：

- 原有分层种子与确定性种子；
- 从前一帧候选出发的容差盒连续 IK；
- 从后一帧候选反向出发的容差盒连续 IK；
- 分层产生的工具轴和完整姿态适配候选。

每帧组成左右候选笛卡尔积，删除所有不满足双臂状态碰撞和 15 mm 指定间隙的组合。相邻帧之间仅建立同时满足以下条件的有向边：

- 两臂关节速度与单帧跳变限制；
- 双臂扫掠碰撞为零；
- 边端点都通过严格 6D FK 复核。

在该图上使用后向价值函数加前向动态规划选择路径。目标采用字典序：

1. 最大化同步成功帧数；
2. 最大化不调整原始姿态即可成功的帧数；
3. 最小化最长连续失败区间；
4. 最小化工具轴和完整姿态的累计偏离及变化率；
5. 最小化重新进入可跟随状态的代价；
6. 最大化最小几何间隙；
7. 最大化奇异值和关节限位余量；
8. 最小化关节路程。

若某帧不存在安全节点或不存在安全入边，规划器进入显式恢复状态并记录根因，不把保持帧算作跟随成功。恢复状态只能通过现有速度、步长、状态碰撞和扫掠碰撞检查后转移；它不会修改目标或时间戳。

## 5. 软件边界与接口

### 候选生成层

文件：`factory_bimanual/mujoco_candidate_generator.py`

- 增加严格容差盒求解方法，输入目标位姿、参考关节状态和候选预算。
- 增加分层姿态候选生成接口，输入原始姿态、固定标定、工具轴/摆动范围以及相邻帧姿态偏移参考。
- 复用现有 FK、Jacobian、关节边界和误差计算，避免形成第二套容差定义。
- 返回结果沿用现有候选数据结构，并增加来源标签和优化终止原因。
- 所有缓存键必须包含机械臂侧、目标帧、参考状态量化值、标定和 mount 标识。

### 联合图构建与选解层

文件：`factory_bimanual/collision_safe_follow.py`

- 新增离线 paired-graph 求解模式，不直接替换现有 beam 模式。
- 将“安全 paired node”“安全 transition edge”“recovery state”建模为独立数据结构。
- 状态和扫掠碰撞检查继续调用统一碰撞适配器。
- 候选层、paired node 和 transition edge 支持缓存，避免动态规划中重复 MuJoCo 审计。
- 保留现有 beam 求解作为基线和失败回退路径，便于逐区间比较。

### 命令与渲染入口

文件：`scripts/render_factory_dual_piperx_fixed_time.py`

- 增加显式求解器配置，例如 `paired-global`，默认行为在完整回归通过前保持不变。
- 姿态适配预算、软限制和绝对上限由配置显式记录，禁止使用未记录的逐帧自由旋转。
- 支持只重算指定帧区间并输出诊断，不要求每次都渲染全片。
- 完整渲染必须读取锁定的左右标定四元数和最终 mount，不在渲染时重新优化。

## 6. 诊断与结果数据

修正当前 paired 诊断中把 `followed` 布尔值当作候选数的记录方式。每帧至少保存：

- 左右原始严格候选数；
- 左右容差盒补充候选数；
- 状态碰撞过滤前后的 paired node 数；
- 可连接入边与出边数；
- 最佳节点的位姿误差、最小间隙、奇异值和关节限位余量；
- 原始/适配目标四元数、工具轴偏移、摆动偏移、偏移速度和适配层级；
- 失败根因：单臂严格 IK 不可达、paired 状态冲突、动态边不可连接、扫掠边冲突或恢复失败；
- 求解器模式、候选预算、缓存命中率和各阶段耗时。

这些字段用于判断覆盖率提升来自真实安全连接，而不是停住、漏检碰撞或统计口径变化。

## 7. 性能控制

- 先在失败密集区间运行，不直接对 1964 帧使用最大预算。
- 只有原始候选缺少安全连接时才触发 reference-aware 补充求解。
- 参考状态先按周期关节距离聚类，再选择有限个代表，避免每个 beam 节点都启动优化器。
- paired node 先用快速几何下界筛选，再进行完整 MuJoCo 接触和指定间隙检查。
- transition edge 使用关节速度下界先剪枝，再做扫掠碰撞审计。
- 将候选层、碰撞节点和边结果持久化，使参数调整不必重复运行全部 IK。
- 每个阶段配置硬候选预算和超时；超时帧记录为预算耗尽，不能误报成物理不可达。

## 8. 测试策略

### 单元测试

- 构造零残差解离参考状态较远、容差盒内另有更近严格解的案例，验证新求解器返回更可连接的候选。
- 验证 1.0001 mm 或 1.5001° 的候选被拒绝，边界内候选被接受。
- 验证周期关节的距离、去重和速度计算一致。
- 验证 source timestamp、目标位置和只读保存的原始四元数在求解前后逐元素不变；适配四元数写入独立字段。
- 验证原始四元数只读保存，适配四元数单独记录，且偏移不超过配置的绝对上限。
- 验证姿态适配的一级、二级连续性代价能抑制单帧翻腕和偏移跳变。
- 验证只有更低层级不存在安全连接时才开放更高自由度姿态适配。
- 验证真实左右候选数、paired node 数和 edge 数写入诊断。

### 图规划测试

- 构造前向局部最优分支在未来断裂、当前略贵分支可以完整通过的图，验证后向价值函数保留未来可行分支。
- 构造状态碰撞节点和扫掠碰撞边，验证无论代价多低都不会被选择。
- 构造无安全节点帧，验证进入恢复状态且该帧不计为跟随成功。
- 验证全局模式失败时回退到原 beam 不会放宽任何硬约束。

### 真实区间回归

- Seal Bag：第一秒及约 133–317 帧的 branch/dynamic 密集区间。
- Fold Box：约 666–912 帧的状态碰撞密集区间，以及约 1361–1499 帧的 branch 密集区间。
- 每个区间同时运行旧 beam 和新 paired-global，比较逐帧根因、成功率、最长失败段、最小间隙和运行时间。

## 9. 验收标准

进入完整轨迹重算前，代表区间必须同时满足：

- 最终状态碰撞为 0，扫掠边碰撞为 0。
- 指定跨臂几何对最小间隙不低于 15 mm。
- 所有成功帧位置误差不超过 1 mm、姿态误差不超过 1.5°。
- 原始时间戳和位置目标完全未变，无重定时；原始姿态保留，适配姿态及偏移完整可审计。
- 工具轴偏移与摆动偏移均不超过配置的绝对上限，且不存在未解释的逐帧跳变。
- 新模式的同步成功帧数高于旧模式，或在成功帧数相同的情况下缩短最长连续失败段。
- 不通过保持、恢复或不可达帧改变成功统计。
- 运行时间和缓存数据规模在配置预算内，且预算耗尽能够被单独识别。

代表区间通过后，才对 Seal Bag 和 Fold Box 完整轨迹重算并渲染。完整结果需报告：严格同步覆盖率、失败类型分布、最长连续失败段、状态/扫掠碰撞数、最小间隙和总运行时间。

## 10. 实施顺序

1. 修复并扩展诊断字段，为后续比较建立可信基线。
2. 联合搜索两个任务共用的左右固定标定微调，并锁定结果。
3. 以测试驱动方式实现分层姿态适配和严格容差盒连续 IK。
4. 在 Seal Bag 第一秒接入按需补充候选，确认 dynamic/branch 失败减少且无姿态跳变。
5. 实现 paired node 与 transition edge 缓存及离线图结构。
6. 实现后向价值函数和联合动态规划，在合成图测试中验证未来分支保留。
7. 对 Seal Bag 与 Fold Box 指定失败区间进行旧/新求解器对照。
8. 根据诊断限制姿态与候选预算，不改变位置、时间、动力学和碰撞硬约束。
9. 完整重算两个任务，执行碰撞、误差、姿态偏移、时间戳和统计审计。
10. 只有完整验收通过后才渲染并上传新视频及配套诊断。

## 11. 明确不包含的改动

- 不改变官方手爪相对法兰的固定旋转；只优化手持数据坐标系到 PiperX TCP 的固定标定，并允许受限的任务姿态适配。
- 不重新搜索 mount；如果严格安全 IK 静态上限仍构成主要瓶颈，再单独启动 mount 搜索阶段。
- 不允许无界工具轴旋转或无连续性约束的逐帧姿态优化。
- 不进行位置轨迹平滑、位置投影、时间插值或重定时。
- 不以增加随机种子、无限扩大 beam 或全量暴力笛卡尔积作为主要方案。
- 不把仿真不可跟随帧伪装成成功帧。

## 12. 预期结果与边界

该方案先通过共享固定标定和有界姿态适配提高静态安全可达上限，再回收静态上限与最终跟随覆盖率之间的规划损失，因此预期同时改善 pose-unreachable、dynamic 和 branch 失败。对于在允许姿态范围内仍无安全 6D IK、或所有候选均发生双臂碰撞的帧，本方案只会给出更准确的不可达分类，不会突破配置上限。若全局规划后仍接近新的静态安全覆盖上限，下一阶段应回到带间隙的 mount 联合搜索，而不是继续扩大逐帧姿态自由度。
