# PiperX 多任务 Fixed-Time 四构型研究设计

## 目标与范围

对 `data/factory/` 下全部非 `_rejected_short` 双手 CSV 执行 PiperX fixed-time 安装构型与 IK 对比。当前数据集包含 27 条轨迹、12 个任务族；每条轨迹分别评估现有优化基线、桌面正立、墙面或立杆横装、顶部倒挂，共 108 组实验。

## 不变量

- 每组实验直接使用原始采集时间戳，不重定时、不插帧、不增加时长。
- IK 接受门为标定 TCP 位置误差不超过 1 mm、姿态误差不超过 0.5°。
- 第 0 帧采用确定性多启动，后续逐帧 warm-start；失败帧 HOLD，下一帧从保持状态继续。
- 所有构型使用同等搜索预算。构型不可行、IK 失败、碰撞和动力学超限必须保留，不得从聚合统计中删除。
- 逐帧记录左右臂 ACCEPT、双臂同时 ACCEPT、误差、HOLD 原因、碰撞、扫掠边碰撞、双臂拓扑、奇异度、关节余量、速度和加速度。

## 构型与搜索

`baseline` 使用仓库当前任务级推荐底座作为比较锚点。`upright_table` 的安装轴竖直向上；`horizontal_wall` 的安装轴水平面向任务工作区；`inverted` 的安装轴竖直向下。每条轨迹、每种非基线构型独立执行几何粗筛、第 0 帧锚定门、稀疏连续探针、严格全轨迹决赛。排序首先最大化双臂 fixed-time 同时 ACCEPT，其次最小化状态与扫掠碰撞、结构交叉、最长 HOLD、峰值误差和动力学超限。

顶部倒挂允许联合搜索任务级工具姿态与腕部分支；如果同等预算下仍无可行解，结论记为不可行，不通过放宽 1 mm / 0.5° 门限制造成功。

## 工件

每个实验写出 summary JSON、trajectory NPZ、scene XML、manifest/provenance。每条源轨迹生成一个 2×2 同步 MuJoCo 对比视频，四格共享原始时间、相机尺度和颜色语义：绿色 FOLLOW、橙色 HOLD、红色碰撞、蓝色实际 TCP、灰色未来目标。安装面按桌面蓝、墙装橙、倒挂紫、基线灰显示，且用安装轴箭头明确底座方向。

## 聚合与报告

最终 PDF 覆盖全部 27 条轨迹而非只覆盖两个任务。总览包含任务 × 构型双臂 ACCEPT 热力图、构型胜者数量、任务族分布、碰撞与拓扑门、最长 HOLD、位置与姿态误差、奇异度、关节余量、速度/加速度审计。每条轨迹有四构型结果表与同步截图；正文分析代表性成功、失败、构型反转和顶部倒挂阴性案例。图表结构参考用户提供的两份 PDF，但所有数字只来自本次可复现 manifest。

## 验证与发布

验证器要求任务清单精确等于当前 27 条有效双手 CSV，四构型记录齐全，时间戳身份成立，工件哈希一致，视频可完整解码，聚合数字可以从逐帧 NPZ 重算。最终工件写入新的报告目录，不覆盖现有双任务 fixed-time 版本；完成后更新 README、提交并推送 GitHub。
