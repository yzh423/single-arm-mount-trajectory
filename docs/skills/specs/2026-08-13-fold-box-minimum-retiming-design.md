# Fold Box 全局最小必要增时设计

日期：2026-08-13

## 目标

保持 Fold Box 每帧双臂 TCP 位置、四元数、帧顺序和 mount 不变，允许总时长按
严格位姿 IK 分支的实际关节速度需求最小程度增加，以减少
`SOURCE TIMING INFEASIBLE` 和 `RECOVERY PROPAGATION`。

## 求解流程

1. 生成当前每帧最多 8 个严格 6D MuJoCo IK 候选，并过滤状态碰撞候选。
2. 使用 `select_minimum_retime_path` 对每个机械臂执行全轨迹动态规划。
3. 有限关节使用普通差值，显式 continuous hinge 才使用周期最短差值。
4. 相邻候选必须通过 swept collision 检查，并限制单关节分支步长 35°、腕部三关节
   合成步长 45°，防止用延长时间合法化明显翻腕分支。
5. 每条边所需时间为源间隔与关节最短时间的最大值，速度上限为 3.14 rad/s。
6. 左右臂共享时间轴，每条边采用左右臂所需时间的最大值。
7. 不设置总增时上限；输出实际增加秒数和百分比。
8. 正常 retimed 边属于成功跟随，不触发 bounded recovery 或不能跟随标签。

## 诊断

- `retimed`：精确位姿可达，通过增加该边时间满足速度限制；
- `POSE UNREACHABLE`：该帧没有严格 6D IK 候选；
- `COLLISION BLOCKED`：候选状态或所有连续边被碰撞过滤；
- `BRANCH STEP BLOCKED`：只有超过视觉分支步长的候选连接；
- `RECOVERY PROPAGATION` 不应由正常 retiming 产生。

## 产物

NPZ 保存源时间、执行时间、源间隔、共享执行间隔和左右臂所需间隔。Summary 保存：

- 源总时长、执行总时长、增加秒数和百分比；
- retimed 边数、最大单边增时；
- 左右臂严格覆盖率和同步覆盖率；
- 重定时后峰值关节速度与违规数；
- 状态和 swept-edge 碰撞统计。

## 验收

- 速度不超过 3.14 rad/s；
- 碰撞帧为 0；
- 每个执行间隔不短于源间隔；
- TCP 位置和四元数目标不被修改；
- 正常 retimed 边不被标记为不能跟随；
- 视频完整解码，正面 1280×720、60 fps；
- 与当前固定时间方案比较实际增时、覆盖率和剩余失败窗口。

## 限制

该方案与 Seal Bag v4 一样只提供位置级 IK、速度和碰撞可行性，不证明真实硬件的
加速度、jerk、力矩或闭环 MPC 可执行性。
